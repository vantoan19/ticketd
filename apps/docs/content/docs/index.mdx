---
title: Introduction
description: A local ticket workspace with a desktop app for people and a CLI for agents, sharing the same work and context.
---

ticketd organizes workable outcomes and the context that supports them. It has two
ways in, and both open the same workspace on your computer:

- **The desktop app** is where you plan, read and review. You see every ticket,
  Document, Plan and update in one place.
- **The `ticketd` CLI** is how agents take part. Any agent that can run a shell
  command can read context, create tickets and report progress.

Because both use one local workspace, what your agent writes through the CLI is
what you read in the app.

## What ticketd keeps together

| You have                   | ticketd calls it                                          |
| -------------------------- | --------------------------------------------------------- |
| An outcome to reach        | A [ticket](/docs/concepts/tickets)                        |
| A spec, draft or note      | A [Document](/docs/concepts/context)                      |
| Tickets with one objective | A [Plan](/docs/concepts/context#plans)                    |
| "This must finish first"   | A [blocking dependency](/docs/concepts/readiness)         |
| A progress update          | An [Activity](/docs/concepts/activity-and-evidence)       |
| A pull request or a check  | [Evidence](/docs/concepts/activity-and-evidence#evidence) |
